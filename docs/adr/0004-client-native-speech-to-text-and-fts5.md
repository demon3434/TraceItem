# 0004: 面向老幼群体的极简语音寻物与端侧语音转写架构

## 上下文与决策背景
在家庭寻物场景中，核心高频使用者往往包括老人和孩子：
1. 老人和小孩极其不习惯手机键盘打字，复杂的下拉筛选、拼音输入体验门槛极高。
2. 寻物场景具有极强的高时间敏感性——“找东西的时候往往都挺着急的”（如找指甲刀、降压药、备用钥匙、准考证），要求能够“一键按住说话，立刻找出位置”，操作链路必须极度便捷且响应零等待。

经决策，重构语音交互体系：废弃服务端重型的 ASR 模型流式计算，全面启用**客户端原生中文语音听写 + 服务端毫秒级 SQLite FTS5 全文与拼音索引**。

## 架构决策与选型理由
1. **老幼零门槛交互**：
   - App 首页搜索框提供显眼的“语音寻物”大按钮，用户单手长按说话（如“电风扇在哪”、“去年的红围巾放在哪了”），松手即刻完成端侧转写并自动触发检索。
2. **端侧原生算力**：
   - 依赖 iOS（Siri 听写引擎）与 Android（系统语音识别 / 离线输入法引擎），免流、免模型下载、零服务器开销。
3. **服务端极速轻量检索**：
   - 服务端提取识别关键词，在 SQLite FTS5 虚拟表中跨字段（物品名、品牌、分类、标签、位置细化、备注）进行 BM25 智能加权匹配，返回带大图封面与空间路径的卡片流。

## 用户补充细节
> **专栏：用户针对该项提出的补充与扩展**
- **核心受众场景画像**：明确此需求的主要目标用户是老人和小孩，其行为习惯是不习惯打字。
- **痛点不对称性考量**：“录入可以一次性受点累，但是查找的时候一般都挺着急的，所以希望能便捷。” 架构必须全力偏向“寻物阶段”的极低交互摩擦力，确保在急用物品时数秒内锁定位置。
- **服务端卸载**：服务端彻底移除 `sherpa-onnx` 与 `FunASR` 等高内存消耗的推理组件，将家庭服务器资源全部留给存储与网络 I/O。
