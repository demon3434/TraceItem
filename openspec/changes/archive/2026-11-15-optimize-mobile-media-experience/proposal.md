# Proposal: 移动端多媒体体验升级、本地LRU持久化缓存与排版重构

## Why

在家庭私有云部署场景下，移动端通过公网/外网线路（如 DDNS、内网穿透反代等，家庭宽带上行通常受限于 30Mbps 且伴随网络抖动与高延迟）访问物品多媒体附件时，存在明显的体验痛点：
1. **播放每次卡顿重载**：Flutter 官方的 `video_player` 与 `audioplayers` 插件默认仅作内存临时拉流，不具备本地磁盘持久化缓存能力；且本机刚刚拍摄/录制的音视频在上传后即断链，点开详情再次从外网慢速下载，产生 1~2 秒的卡顿等待感；
2. **详情页布局繁冗失焦**：物品详情页将大尺寸图片、大视频播放器与音频播放器一路向下平铺，首屏被巨型媒体占满，核心的位置路径、数量、规格、标签与备注等文本信息全部沉底，严重违背物品查找直觉，界面拥挤缺乏呼吸感；
3. **时长与附件限制不合理**：原先预设的视频 15 秒过短，在真实走位记录与柜门抽屉暗格展示中往往拍到一半被迫截断；且前端代码硬编码仅允许 1 个视频与 1 个音频，无法多角度立体记录物品状态；
4. **缺乏加载透明度与画质分级**：多媒体缺乏半透明文件大小提示，弱网加载无心理预期；且视频锁定单档分辨率，无法兼顾弱网极致省流与说明书超清特写。

因此，亟需对全端多媒体单一数据源（SSOT）、移动端本地磁盘缓存管理、画质预设及详情页信息架构进行系统性升级重构。

## What Changes

- **单一数据源 (SSOT) 扩展与零硬编码**：
  - 在 `shared/media_limits.json` 中规范附件数量上限：**图片 9 张（九宫格）、视频 3 个、音频 3 条**；
  - 放宽最大录制时长：**视频放宽至 60 秒**，**音频放宽至 120 秒**；
  - 沉淀图片压缩基准（长边 1600px、质量 82%、缩略图 300px/75%）；
  - 引入 4 档视频质量预设：`360p` (极速省流)、`480p` (流畅标清)、`720p` (高清标准·默认)、`1080p` (超清细腻)；
  - 默认多媒体缓存配额设为 `200 MB`。
- **移动端类 Telegram 磁盘 LRU 缓存池 (MediaCacheManager)**：
  - 采用有上限的磁盘缓存机制，默认配额 200MB（支持用户在设置中自定义 100MB / 200MB / 500MB / 1GB）；
  - 针对音视频，先查本地缓存，命中则直接走 `File` 本地播放（0ms 秒开），未命中则下载并异步落盘；
  - **上传即命中**：本机拍摄/录制成功的本地文件在上传后自动沉淀为本地缓存并绑定服务端 URL 索引，本机回看零等待、零外网流量；
  - 实施 LRU（最近最少使用）淘汰算法，超额时按最后访问时间清理冷数据至 80% 安全水位线；
  - 设置页展示当前已用缓存体积与进度条，支持一键清空多媒体缓存。
- **详情页信息架构重构（文本优先 + 媒体区块化）**：
  - **文本置顶**：物品名称、位置层级路径（房屋 > 房间 > 详细位置）、品牌、数量、分类、标签与备注长文本置于首屏最上方，一眼看全核心信息；
  - **照片区块（九宫格/缩略图横排）**：轻量加载 300px 缩略图，右上角半透明药丸展示 `尺寸 | 大小`，点击弹出全屏高清画廊与手势缩放；
  - **视频区块（封面海报卡片）**：以首帧封面 + 播放小徽章呈现，浮层展示 `时长 | 文件大小`，未点击时不初始化重型播放器，点击后展开或沉浸播放；
  - **音频区块（极简胶囊条）**：消除沉重波形图与冗余参数，仅保留播放/暂停微按钮、`mm:ss` 时长与文件大小胶囊。
- **多媒体统一半透明尺寸徽章**：
  - 图片、视频、音频组件统一增加多巴胺半透明磨砂药丸徽章（`12px` 字号，半透明黑底 + 微光描边），提供明确的文件体积与加载等待预期。
- **服务端 HTTP 静态分发强化**：
  - 在 `/api/media/file/{file_path}` 响应中补充 `Cache-Control: public, max-age=31536000, immutable` 强缓存响应头与 ETag 协商，加速 Web 端与代理缓存复用。

## Capabilities

### New Capabilities
- 无（沿用现有架构体系，深化多媒体与性能表现）。

### Modified Capabilities
- `shared-constants-ssot`: 扩展 `media_limits.json`，补充附件数量上限（9图/3视/3音）、放宽音视频时长（60s/120s）、预设 4 档视频画质参数与 200MB 默认缓存上限，重新生成双端代码。
- `mobile-media-and-performance`: 更新移动端多媒体规范，涵盖详情页文本优先排版、媒体轻量区块化展示、半透明尺寸药丸、类 Telegram 200MB LRU 本地缓存池（上传即命中）以及 4 档视频画质偏好设置。

## Impact

- **共享配置与生成代码**：`shared/media_limits.json`，`mobile/lib/core/generated/shared_media_limits.g.dart`，`server/app/db/constants.py`。
- **移动端核心逻辑**：
  - 新增 `MediaCacheManager` 管理本地磁盘音视频缓存、URL 映射与 LRU 水位线淘汰；
  - 重构 `ItemDetailScreen`，拆分为 `ItemDetailHeaderInfo`、`ItemDetailImageGrid`、`ItemDetailVideoSection`、`ItemDetailAudioSection`；
  - 升级 `DopamineVideoPlayer`、`DopamineAudioPlayer`、`ItemDetailGallery` 支持半透明大小徽章与本地 File 直播；
  - 升级 `ItemEditMediaSection`，支持图片 9 张、视频 3 个、音频 3 条的上限边界与上传文件就地转存缓存；
  - 升级 `SettingsScreen`，提供缓存配额管理、实时体积查看、清空缓存与视频画质偏好选择。
- **服务端接口**：
  - `server/app/api/media.py` 补充 `Cache-Control` 强缓存响应头；
  - API 层同步校验图片 ≤9、视频 ≤3、音频 ≤3 的数量约束。

## Phase 2 补充范围：录入体验、三段式媒体区块重构与细节打磨

基于移动端真机实测反馈，本变更补充第二阶段体验打磨，重点解决以下 6 项问题：
1. **录音弹窗计时器去硬编码**：修复 `AudioRecordSheet` 计时分母写死 `01:00` 与分钟进位问题，全面读取 `shared/media_limits.json` 的 `audioMaxDurationSeconds`。
2. **录入页表单顺序重构**：将 `ItemEditScreen` 中的多媒体附件录入区从顶部移至表单末尾（保存按钮上方），回归「核心文本优先」的高效录入动线。
3. **音视频按钮文案读取共享配置**：录像/录音按钮统一展示为 `"xx分钟短视频"`、`"xx分钟录音"`，时长由 `shared/media_limits.json` 动态计算。
4. **编辑页与详情页三类媒体彻底分区重设计**：废除拥挤的头部计数字符串与混排 `Chip`，将照片、视频、语音拆分为 3 个独立且视觉统一的现代区块；每条已上传附件均以缩略图/海报卡片/胶囊条展示文件大小与时长，并支持点击直接预览/播放；详情页 `ItemDetailScreen` 采用完全一致的审美与结构规范。
5. **数量步进器与防错约束**：数量输入框限制仅允许正整数（`>= 1`），右侧新增 `-` / `+` 步进辅助按钮，修复边缘裁切问题。
6. **Placeholder 文案全量统一**：所有文本输入框统一规范为 `"如：..."` + 具体业务示例。

## Phase 3 补充范围：实测修复、封面强约束、卡片与空间管理体验重设计

基于真机实测与视觉审阅，追加第 3 阶段 9 项重点优化与缺陷修复：
1. **全局 Toast 气泡定位与强反差配色**：修复底部 Toast 被系统手势导航条遮挡的问题，并改为深色高反差底色配浅色文字。
2. **数量步进器改用右侧上下叠放微箭头**：在输入框最右侧垂直排布上/下增减箭头，替代横向加减按钮。
3. **根治图片缩略图/预览/保存链路 Bug**：修复上传返回相对路径缺少 `/api/media/` 前缀导致的 404 问题，以及编辑态回填 `thumbnail_url` 导致的双前缀保存死链。
4. **编辑页同类别多媒体拖拽排序**：照片、视频、语音数量 ≥2 时均支持拖拽调整先后顺序，首张照片决定封面顺序。
5. **强制至少保留 1 张实景照片**：新增/编辑提交时校验至少存在 1 张图片附件，且第 1 张自动作为物品卡片封面图。
6. **编辑页录音原地直接播放**：取消语音弹窗试听，改为列表卡片内直接点击播放/暂停。
7. **详情页底部操作栏纯图标精简**：删除与编辑按钮仅保留垃圾桶与铅笔小图标，去掉冗长文字以缩小按钮体积。
8. **物品卡片（`MobileItemCard`）重设计**：去掉品牌文字、去掉数量 `x` 前缀、多媒体角标去文字化仅留图标、长位置文本防折行、封面图采用自适应完整展示策略避免裁切物品主体。
9. **房屋与房间管理页减噪重构**：移除房屋卡片中的「当前房屋」标签、房间数量文案与「+ 加房间」按钮以完整展示房屋名称；移除「短按查看 · 长按拖拽排序」文案；取消点击房间直接跳转物品列表的误触行为。

## Phase 4 补充范围：路径前缀根治、详情页弹窗自动播放、画廊左右滑切换与按钮视觉对齐

2. **详情页底部双按钮等宽与主次反差**：删除按钮改为醒目红底白图标，编辑铅笔按钮改为低视觉权重浅色描边配色，且两者尺寸完全一致（`56x44`）。

## Phase 5 补充范围：全屏媒体预览、手势缩放修复、图片旋转与编辑卡片轻量化

基于真机实测体验反馈，追加第 5 阶段 5 项预览与编辑交互优化：
1. **全屏沉浸式图片与视频预览**：详情页与编辑页的图片、视频附件点击后均改为真正全屏放大预览（替代带边距弹出层），屏幕右上角固定醒目红叉关闭按钮。
2. **修复图片双指缩放 Bug**：解决 `PageView` 与 `InteractiveViewer` 手势冲突导致的双指无法捏合缩放问题，确保 1.0x~4.0x 捏合缩放丝滑可用。
3. **全端图片左右滑切**：详情页与编辑页点击任意图片进入全屏画廊后，均可左右滑动切换前后图片。
4. **编辑页三类附件卡片右上角微红叉与左下角整数尺寸**：照片、视频、语音卡片右上角统一改用紧贴角落的小尺寸红叉删除按钮以减少遮挡；图片与视频缩略图左下角贴边显示无小数文件尺寸（如 `269 KB`、`17 MB`）。

## Phase 7 补充范围：生产级多媒体孤儿文件防误删与全生命周期闭环

针对「先上传、后提交」预上传模式及软删除审计机制可能产生的孤儿与冗余占用问题，追加第 7 阶段生产级闭环治理方案：
1. **孤儿扫描/清理增加时间保护期（Grace Period）**：为服务端 `get_all_orphan_files` / `clean_orphan_media` 引入默认 1 小时（`3600s`）文件修改时间保护窗口，确保 Admin 执行清理时绝不误删家庭成员正在编辑、上传或旋转中的临时文件。
2. **客户端编辑会话级临时附件即时回收**：服务端新增安全回收接口 `POST /api/media/cleanup-temp`（仅允许清理 `Attachment` 表未引用的沙箱路径）；移动端编辑页追踪本次会话新上传/旋转产生的未入库附件，当用户移除未保存附件、连续旋转替换中间版本或放弃编辑返回时，异步通知服务端即时删盘回收（断网/闪退由保护期后的孤儿清理兜底）。
3. **软删除物品媒体审计与可控彻底清理**：在 Admin 孤儿审计与存储统计中补充「已软删除物品占用媒体」统计，并提供可控的彻底清理能力（清理已软删除物品记录及关联物理文件），解决长期使用后软删除附件只增不减的问题。
