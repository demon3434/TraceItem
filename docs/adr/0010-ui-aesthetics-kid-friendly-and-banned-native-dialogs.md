# 0010: UI美学规范、儿童友好设计与全面禁用原生 Alert/Confirm 弹窗

## 上下文与决策背景
在以往的 Web 与移动端开发中，经常出现以下破坏体验的现象：
1. 开发者为图省事，在删除确认、错误提示、操作拦截时直接调用浏览器原生的 `alert()`、`confirm()` 或未样式的系统级弹框，样式极其生硬，割裂了精美界面的整体视觉感；
2. 界面设计偏向冷漠的企业工单风格，忽略了家庭场景中儿童是高频使用者（找玩具、文具、零食），界面缺乏亲和力与童趣。

经决策，全面确立**“严禁使用原生弹窗（全量采用 Shadcn 统一弹出层）+ 儿童友好活力主题（多巴胺马卡龙色板、20px 温润圆角、Emoji 空间图腾）”**的全局 UI/UX 规范。

## 架构决策与选型理由
1. **全面清退原生弹窗 (Banned Native Alerts)**：
   - 严禁在任何 Web 前端代码中使用 `window.alert()`、`window.confirm()`、`window.prompt()`；
   - 严禁在移动端使用未经定制的原始系统 Dialog；
   - **统一收口到自定义组件层**：
     - 二次确认与重要阻断：Web 采用 `ShadDialog` / `ConfirmModal`；Flutter 采用 `showShadDialog`；
     - 空间选择与筛选：全端采用温润半屏抽屉 `ShadSheet`；
     - 轻量通知与状态反馈：统一使用 `Sonner` / `ShadToaster` 浮动气泡，具备柔和触感与自动退场。
2. **多端设计底座统一**：
   - 移动端基于 [`flutter-shadcn-ui`](.agents/skills/shadcn-ui-flutter/SKILL.md)；Web 端基于 `shadcn-vue` + Tailwind CSS；
   - 图标全端 100% 统一为 **Lucide Icons**，杜绝图标风格杂乱。
3. **儿童友好美学 (Kid-Friendly Aesthetics)**：
   - 采用 **18px ~ 24px 大圆角（Squircle）**，消除冷硬感；
   - 预设 6 套马卡龙与活力多巴胺色板（阳光暖橙、草莓甜心、薄荷清柠、星空城堡等），支持一键换肤；
   - 房间与分类强制支持 **Emoji 趣味图腾**（如 🧸 玩具角、🚀 秘密基地、🛋️ 大客厅），让不识字的孩子也能看图辨识。

## 用户补充细节
> **专栏：用户针对该项提出的补充与扩展**
- **严禁偷懒使用原生弹窗**：“弹出确认、弹出消息，我就不希望每次都跟你说，‘不要用alert、confirm，请你自行设计弹出层’。” 必须将此项作为自动化审查硬指标，杜绝原生丑陋弹窗。
- **杜绝每次重复提醒设计美化**：“我也不想每次生成一个openspec提案，都跟你说一遍界面美化的事情。” 必须将设计系统规则固化到 OpenSpec 自动化引擎与 Agent 规则体系中。
- **儿童友好与色彩多样性**：“我希望软件的配色也多样化一些，孩子用得多，也需要软件更漂亮可爱一些。” 确立童趣与高级感兼备的设计基调。
