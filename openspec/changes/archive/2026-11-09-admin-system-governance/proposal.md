# Proposal: Admin 治理中枢升级、全量软删除原则与空间利用彻底重构

## Why

在用户对当前 Admin 账号与界面的深度审查中，指出了系统在业务边界、底层数据原则与 UI 空间布局上的多项关键问题：
1. **全系统删除机制不合规**：此前部分实体存在直接物理删除，违背了“本系统的一切删除均为状态标志软删除，绝非物理 delete”的核心原则。
2. **Admin 角色边界与寻物工具缺失**：Admin 必须是严格只读的系统管理员（绝不可修改用户私有数据），但需具备托底寻物能力。现有的简单搜索无法满足实际需求，亟需贴合实际运维的“多维级联托底寻物”（按用户 ➔ 房屋 ➔ 房间 ➔ 分类 ➔ 标签 ➔ 关键词 ➔ 时间范围）。
3. **隐私绝对隔离**：普通用户之间必须保持 100% 独立私有，绝不引入家庭协同或物品跨成员可见。
4. **存储与灾难恢复机制残缺**：磁盘多媒体孤儿文件无法扫描和一键清理；TAR 备份仅能生成和下载，缺少从历史记录、手动上传、以及应对超大文件的“服务器指定目录 (`/data/media/backups/import/`) 扫描并恢复”的闭环能力。
5. **Admin 无法修改自身密码**：缺乏自主修改密码入口，存在弱口令风险。
6. **UI 空间极度浪费与逻辑混乱**：
   - 用户卡片上存在无效的“家庭成员”生硬标签；
   - 页面顶部占据大面积的“系统管理中枢控制台”大黄横幅套话；
   - 中间内容区与左侧菜单栏重复放置 Tab 切换条，且全局指标卡片挤占工作区；
   - 需要将展示性指标上移至顶部标题栏，取消大横幅与重复 Tab，让左侧菜单直接作为独立页面路由，主内容区 100% 满屏展示专属功能，彻底释放屏幕空间。

## What Changes

### 1. 全局软删除架构原则 (Soft-Delete Everywhere)
- 系统中所有实体（用户、房屋、房间、物品、分类、标签等）统一采用软删除标志（`is_deleted = True`），所有常规查询自动过滤已删除数据，杜绝物理 `DELETE`。

### 2. Admin 严格只读定位与多维托底寻物中枢
- **严禁数据篡改**：Admin 不允许修改任何用户的私有数据，保持纯只读托底。
- **多维级联寻物界面**：提供按“用户 ➔ 房屋 ➔ 房间”级联过滤，并组合分类、标签、关键词、录入时间区间的全景托底查物面板，精准帮助用户定位遗忘物品。

### 3. 多媒体磁盘孤儿文件一键清理
- 后端扫描 `/data/media/` 物理磁盘文件，与数据库 `attachments` 表校验对比，统计未引用的孤儿文件数量与体积；
- Web 端提供可视化审计结果并支持一键物理清除，释放磁盘存储。

### 4. 三模闭环 TAR 灾难恢复机制 (Disaster Recovery)
- **模式 A（历史快照恢复）**：从已存在的备份记录列表一键选择并恢复。
- **模式 B（浏览器上传恢复）**：通过 Web 界面上传本地 `.tar` 备份包触发恢复。
- **模式 C（服务器目录扫描导入恢复）**：针对超大文件（超出浏览器上传限制），引导用户通过 SCP 上传至服务器导入目录（`/data/media/backups/import/`）；Web 端自动扫描解析该目录下的 TAR 包结构，验证其数据库与媒体完整性，列入可恢复记录并一键选定恢复。

### 5. 系统管理员自主密码修改
- 提供 `PUT /api/admin/password` 接口与右上角修改密码对话框，供 Admin 修改自身登录口令。

### 6. UI 页面空间利用彻底重构与文案去中二化
- **剔除无意义标签**：删除用户卡片上红框所标的“家庭成员”标签（保留系统管理员标记，普通成员不贴多余标签）。
- **彻底删除无效横幅**：移除“系统管理中枢控制台”黄色大横幅卡片。
- **全站文案朴素化（去中二与大词）**：全面排查所有界面文案，去除“数据灾备与三模恢复”、“全景收纳”等虚浮词汇，采用朴素平实的工程化文案（如“数据备份与恢复”），软件名纯粹使用“物迹”。
- **指标统计下移至面板标题栏**：4 组核心统计（用户数、物品数、存储大小、最近备份）从全局顶栏中剥离，移入各管理工作台自身的小标题栏空白处，避免在全站每一处都机械出现。
- **用户卡片紧凑排版**：优化用户卡片网格布局（响应式 3~4 列），消除卡片横向过宽与大面积空旷感。
- **多维寻物按钮协调**：“重置条件”按钮增加小刷子/清空图标，并将字号提升至 `text-sm font-bold`，与“开始检索”协调一致。
- **数据库文件解耦更名**：数据库文件彻底去除旧名称 `antusuoji.db`，更名为与软件名称解耦的通用功能名称 `items.db`，TAR 打包与恢复全面兼容。
- **备份防并发与保留策略**：一键生成备份增加弹窗确认与前端按钮禁用/加载状态，后端增加防重复并发提交校验；恢复一键清理过期备份功能，保留策略改为保留最近 3 份；历史备份记录表格增加分页（默认每页 10 条）。
- **菜单路由解耦与 100% 满屏工作区**：
  - 左侧侧边栏作为唯一定位菜单：【👥 用户账号管理】、【🔍 多维托底寻物】、【📦 数据备份与恢复】、【🧹 存储清理审计】；
  - 彻底取消中央内容区的重复 Tab 条，每个功能拥有 100% 独立的满屏操作空间。

### 7. Admin 初始默认口令规整与物品分类模板独立工作台
- **Admin 初始默认口令**：首次建库与初始化部署时，Admin 默认登录口令由原 `admin123456` 统一规范为 `admin123`。
- **全局物品分类模板治理 (增删改停)**：
  - 将硬编码在代码中的 14 种预设分类剥离并下沉为持久化数据库模板 `CategoryTemplate`；
  - 允许 Admin 在后台对系统级分类模板做“增删改停”（创建新分类模板、修改名称/图标/排序、软删除、启用/停用切换）；
  - **新用户动态模板继承**：今后新增的用户，其初始化的个人物品分类直接拷贝自 Admin 当前维护的有效分类模板（`is_active = True` 且 `is_deleted = False`），彻底告别硬编码写死。
  - **Admin 菜单增加专属页面**：在 Admin 侧边栏菜单中新增独立的【🏷️ 物品分类管理】工作区页面，提供专属分类卡片网格、创建/编辑分类抽屉与停用开关。

### 8. 物品分类序号可视化与拖拽/上下箭头重排序
- **序号醒目呈现**：Admin“物品分类管理”中的每个模板小卡片均展示序号标签（如 `#1`、`#2`...）；普通用户在“分类管理”界面中同样直观展示各分类序号。
- **Admin 分类模板重排序**：Admin 可通过卡片上的【向上/向下箭头】（逐步微调）或直接【鼠标拖拽卡片】调整次序，调整后持久化至数据库，后续新增用户继承该模板排序。
- **普通用户私有分类重排序**：扩展普通用户端的分类管理页面/弹窗，同样支持展示序号、上下箭头微调与拖拽排序，保存后即时同步刷新主页分类筛选胶囊。

## Capabilities

### New Capabilities
- `admin-system-governance`: 涵盖全系统软删除、多维托底寻物、多媒体孤儿清理、三模 TAR 灾备恢复及管理员改密。

### Modified Capabilities
- `admin-user-governance`: 剥离无效的“家庭成员”标签，规范用户软删除与只读管理契约。
- `web-admin-security`: 规范 Admin 只读边界、顶部紧凑指标栏、以及三模 TAR 恢复安全机制。

## Impact
- **后端**：在各核心 Model 中确认软删除字段支持；在 `admin_service.py` 与 `admin.py` 中增加孤儿扫描/清理、三模恢复、多维托底检索及改密接口。
- **前端**：重构 `SpaceAnchorBar.vue`、`HouseRoomSidebar.vue`、`MainView.vue`；创建 `MultiDimensionalSearchPanel.vue`、`BackupRestorePanel.vue`、`MediaCleanupPanel.vue`；重构 `UserManagementPanel.vue`。
- **代码规范**：所有新增与重构的单文件行数严格控制在 500 行以内，严禁任何原生 `alert/confirm`。
