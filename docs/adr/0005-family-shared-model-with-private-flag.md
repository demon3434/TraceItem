# 0005: 用户独立私有账本与 Admin“上帝视角”寻物架构

## 上下文与决策背景
在家庭收纳管理中，不同用户（如父母、孩子、老人）对空间命名具有强烈的个性化认知差异（“主卧” vs “妈妈房间” vs “秘密基地”；“父母家” vs “奶奶家”），且每位成员有自己的多套房产与物品归属。
初期曾探讨过全家默认互通及复杂的跨端别名映射方案，但经深入业务场景辨析，发现：
1. 日常情况下，每个人最清晰自己收纳整理的私人物品，强行将所有人的空间混杂在一起反而会造成干扰与隐私顾虑。
2. 当发生突发紧急情况（如老人突发不适需找某类特定药品、全家寻找备用钥匙或证件，而录入者不在身边时），必须存在一种强有力的快速兜底机制。

经决策，重构多用户协作模型：**日常模式下各普通用户为严格的“个人独立私有账本”，互不干扰；同时在 Admin（管理员）后台专设全局“上帝视角（God View）”寻物中枢，Admin 自身不产生日常数据，但具备全库检索与穿透查看能力**。

## 架构决策与选型理由
1. **普通用户：独立私有账本**：
   - 房屋（House）、房间（Room）与物品（Item）严格绑定 `user_id`。
   - 普通用户登录后，仅呈现属于自己的房屋、房间和物品列表，杜绝概念混淆，保护家庭成员隐私。
2. **Admin“上帝视角”寻物中枢**：
   - Admin 账号不用于日常个人物品录入（自身不产生数据）；
   - 在 Admin 管理功能中设置【全局上帝视角寻物】模块：当全家出现紧急寻找公用物品的需求时，由 Admin 账号一键触发跨用户全库检索，直接穿透展示该物品属于哪个用户、存放在该用户命名的哪个房屋、哪个房间，并调阅对应的照片和视频。
3. **架构极简化收益**：
   - 彻底废除客户端复杂的空间别名映射表（`space_aliases`）与视图转换逻辑，数据模型极其干净纯粹。

## 用户补充细节
> **专栏：用户针对该项提出的补充与扩展**
- **私有账本定位明晰**：否定了复杂的跨用户别名映射方案，确定日常各成员使用各自独立的数据空间。
- **Admin 上帝视角定位**：“如果紧急搜索，可以在admin中增加上帝视角的查找物品功能。admin自己不产生数据，但是可以查看所有数据。”
- **权责清晰划分**：Admin 仅承担“账号管理”、“无压缩 TAR 手动备份”与“紧急上帝视角寻物”三大职责，不参与日常杂务录入。
