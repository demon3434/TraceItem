# 0008: 空间预设、免配置橱柜与“空间锚定/手动选择”极简录入流

## 上下文与决策背景
在空间层级与录入流程设计中，曾探讨过更细粒度的容器配置及自动化识别设想。经用户深刻指正：
1. **真实家庭无需过度配置细化橱柜**：“家里总共就这几个柜子，具体的橱柜不需要再配置了，拍照就可以直观知道在哪里了”。如果强制用户在系统里一层层建“电视柜 -> 第二层 -> 红色收纳箱”，录入成本将极其繁重，失去实用价值。
2. **拒绝不可靠的“黑盒自动识别房间”**：用户可能提前在卧室、储藏室拍摄好了多张照片，事后坐到客厅沙发上才统一提交与录入。系统无法也不应凭空臆测用户拍摄时的物理房间。

经决策，回归真实家庭收纳本源：**“房间提前预设 + 橱柜免配置（以图代管）+ 录入时手动单选/空间锚定继承”**。

## 架构决策与选型理由
1. **扁平化空间架构（仅维护到房间）**：
   - 数据库仅维护两级核心实体：`House`（房屋）➔ `Room`（房间）。
   - 取消细化容器、储物格的繁杂配置表。抽屉、柜门、货架的具体形态完全交给“现场照片与短视频”直观呈现，符合“图觅”见图即知位置的理念。
2. **透明直观的房间指定交互（无黑盒识别）**：
   - **预设房间点选**：用户提前建好常用房间（如“客厅”、“主卧”、“地下室”）。
   - **现场整理时的“空间锚定”**：若用户正站在书房批量整理书柜，在界面点选“书房”并点击“锁定当前空间”，后续拍摄的物品默认挂载到“书房”，无需每拍一件重复选择一次。
   - **异地后补录入场景**：若用户在主卧拍摄了照片，事后到客厅提交，界面呈现直观的房间标签胶囊，用户单手点选“主卧”即可精准归档，过程 100% 透明可控。

## 用户补充细节
> **专栏：用户针对该项提出的补充与扩展**
- **橱柜免配置原则**：“房间是提前预设好的，但是具体的橱柜，不需要再配置了，家里总共就这几个柜子，拍照就可以知道在哪里了。”
- **摒弃黑盒自动识别臆测**：“我没懂，你怎么实现自动识别用户在哪个房间的？如果是提前拍照，事后到另一个房间提交照片，你怎么识别？” 确立明确的人工点选/记忆逻辑，杜绝任何假想的“黑盒自动识别房间”。
- **见图知物的视觉留痕核心**：充分利用 JPEG 高清照片与 x265 路径短视频传达橱柜环境，解放用户的数据库建表负担。
