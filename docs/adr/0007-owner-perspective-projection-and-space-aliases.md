# 0007: Admin 全局上帝视角寻物设计（废除复杂别名映射）

## 上下文与决策背景
原 ADR 0007 曾设想过通过复杂的“空间别名映射表（`space_aliases`）”在前端动态转换不同用户的房间叫法。经过业务推演，这种方案存在明显缺陷：
1. 模型过于复杂，移动端与 Web 端需要维护双向映射缓存；
2. 家庭成员之间很少需要实时全量共享彼此所有的琐碎物品；
3. 真正需要跨用户查找的场景几乎全部是**“紧急情况”**（如急找急用公用物资或贵重物品）。

经决策，**正式废止空间别名映射机制，直接确立由 Admin 提供的全局“上帝视角”寻物架构**。

## 架构决策与选型理由
1. **单一数据真相源**：
   - 移除 `space_aliases` 数据表与相关接口，保持数据库极简。
2. **Admin 上帝视角检索链路**：
   - 接口：`GET /api/admin/god-view/search?q={query}`；
   - 权限：仅限 `role = 'admin'` 的用户可调用；
   - 检索能力：在 SQLite FTS5 虚拟表中跨所有用户执行全文检索，结果聚合返回：
     - 物品名称与品牌；
     - 归属成员（属主昵称/账号）；
     - 属主定义的空间路径（如 `爸爸的[阳光城] > [主卧]`）；
     - 完整的图片、语音与视频附件。
3. **安全与审计**：
   - 上帝视角仅作为家庭管理兜底，普通成员端界面保持清爽整洁，没有任何冗余的跨用户配置项。

## 用户补充细节
> **专栏：用户针对该项提出的补充与扩展**
- **方案裁决**：采纳选项 B（各用户私有独立），明确指出紧急搜索需求通过 Admin 上帝视角解决即可，不需要做复杂的全员别名映射系统。
- **Admin 纯粹性**：Admin 账号定位为家庭系统的超级调度员，不参与日常数据生产，但能随时全景俯瞰。
