# 跨平台全模态多媒体系统架构与 UI 工艺参考指南

> **适用场景**：家庭私有云、弱网边缘部署、个人数字资产留痕、消费级移动客户端与跨平台应用。  
> **核心目标**：在有限网络上行（如家庭宽带 30Mbps）、多端存储受限的边界条件下，实现**毫秒级秒开、高保真视觉细节、克制存储占用与旗舰级 UI 触感**。

---

## 一、 核心痛点与架构定位

在私有服务器映射到公网（DDNS / 内网穿透反代 / 手机移动蜂窝网）的场景中，传统应用的多媒体流往往面临三大致命痛点：
1. **外网网络抖动与往返延迟（RTT 50~100ms+）**：即使家用宽带具备数十兆上行，播放器每次拉取未缓存的音视频，都要重复建立 TCP/TLS 握手并经历缓冲区填充，带来 1~2 秒的卡顿等待；
2. **手机存储过度膨胀的恐惧**：如果无节制做离线缓存，应用会沦为“内存刺客”；
3. **技术原型式 UI 排版**：大图与全尺寸播放器一路向下平铺，首屏被巨型媒体占满，核心文字信息（名称、位置、分类、备注）被严重挤压沉底。

本方案通过**「端侧自适应压缩 + SSOT 单一数据源 + 类 Telegram 200MB LRU 缓存池（上传即命中）+ 文本置顶与媒体区块化 UI」**，提供一套工业级、可直接复用的最佳实践。

## 二、 全模态端侧压缩与编码工程标准

### 1. 图片规范：JPEG 兼容性与视觉无损黄金平衡
* **主图规格**：等比缩放限制最大长边 $\le 1600\text{ px}$（短边随比例自适应），统一转码为 **JPEG（质量 82%）**；
* **极速缩略图**：等比缩放限制最大长边 $\le 300\text{ px}$（JPEG 质量 75%），供首屏九宫格与列表卡片毫秒级呈现；
* **EXIF 角度矫正**：在端侧解码前提取 EXIF 旋转标记（`Orientation`），自动执行物理像素重排，彻底消除横拍倒置问题；
* **实测效益**：原始 1200 万~4800 万像素照片（3MB~12MB）被无损压缩至 **150KB~450KB**，压缩率达 **90%~95%**，300px 缩略图仅 **15KB~35KB**。

### 2. 语音指引备忘：极轻量高清晰音频
* **编码格式**：单声道 **AAC / M4A**，目标码率 **48 kbps**；
* **时长上限**：放宽至 **120 秒（2 分钟）**；
* **实测效益**：即使录满 2 分钟，体积仅约 **700 KB**（比一张高清照片还小），在 30Mbps 外网下 0.2 秒传输完毕，支持老人孩子即点即听。

### 3. 空间寻路与细节短视频：x265 编码与秒开流媒体对齐
* **编码格式**：优先采用 **x265 (HEVC) / MP4**，相同画质下比 x264 节省 40%~50% 码率；
* **时长上限**：放宽至 **60 秒**，满足复杂走位与柜门抽屉暗格完整记录；
* **FastStart MOOV 头部前置**：视频封装时必须使用 `+faststart` 将 `moov` 索引元数据块移至文件绝对头部，播放器无需下载全量视频，只需接收前几十 KB 即可瞬间起播；
* **关键帧（GOP/Keyframe）锁定**：严格设置关键帧间隔锁定为 1 秒（`keyint=30/fps=30`），配合客户端播放器毫秒级精准对齐，彻底消除公网拖动进度条卡顿；
* **4 档画质预设 (Video Profiles)**：
  | 档位 | 分辨率 | 目标码率 | 30秒预估体积 | 适用网络与场景 |
  | :--- | :--- | :--- | :--- | :--- |
  | **360P** | 640x360 | 450 kbps | **~ 1.6 MB** | 极速省流、公网弱网、纯大件路径 |
  | **480P** | 854x480 | 800 kbps | **~ 2.8 MB** | 流畅标清、日常综合平衡 |
  | **720P (默认)**| 1280x720 | 1400 kbps | **~ 5.0 MB** | 高清推荐、家庭空间与抽屉暗格 |
  | **1080P** | 1920x1080| 2800 kbps | **~ 10.0 MB**| 超清特写、精密器件与说明书文字 |

## 三、 单一数据源 (SSOT) 共享架构

全端（Web / Flutter Mobile / Python Server）涉及的多模态配额与压缩参数**严禁在各端重复硬编码**，统一沉淀于仓库根目录的 `shared/media_limits.json`：

```json
{
  "maxImageAttachments": 9,
  "maxVideoAttachments": 3,
  "maxAudioAttachments": 3,
  "imageMaxLongEdge": 1600,
  "imageJpegQuality": 82,
  "thumbMaxLongEdge": 300,
  "thumbJpegQuality": 75,
  "videoMaxDurationSeconds": 60,
  "audioMaxDurationSeconds": 120,
  "mediaCacheDefaultMaxMb": 200,
  "defaultVideoProfile": "720p",
  "videoProfiles": { ... }
}
```

* **自动化同步**：通过 `python scripts/sync_shared.py` 自动生成 Dart 类 `SharedMediaLimits` 与 Python 全局常量；
* **零漂移校验**：在 CI/CD 中执行 `python scripts/sync_shared.py --check`，任何不一致均会被严格拦截阻断。

## 四、 移动端本地持久化磁盘缓存体系（类 Telegram 机制）

### 1. 架构流图 (MediaCacheManager)
```
+-------------------------------------------------------------------------+
| 用户发起播放 (视频 / 音频)                                              |
+-------------------------------------------------------------------------+
                                     |
               检查本地缓存 MediaCacheManager.get(mediaUrl)
                                     |
                   +-----------------+-----------------+
                   | 命中                              | 未命中
                   v                                   v
         直接加载本地沙箱文件                启动外网 HTTP 流式播放
       VideoPlayerController.file            VideoPlayerController.networkUrl
          (0ms 延迟，零外网流量)             后台异步调用 downloadAndCache()
                                                       |
                                             下载完成重命名并写入索引
                                                       |
                                           触发容量检查与安全水位淘汰
```

### 2. “上传即命中”闭环 (Upload-then-Cache)
* **痛点**：用户在本机刚刚录制好一段视频并上传成功后，点开详情页却又要通过公网把视频重新下载一遍。
* **解法**：在编辑页上传成功取得服务端返回的相对路径（如 `videos/2026/11/...`）时，立即将本地源文件复制沉淀入 `MediaCacheManager` 的缓存沙箱，并将该相对路径作为索引 Key 绑定。本机用户再次点开时 **100% 命中本地文件**。

### 3. LRU 淘汰与安全水位线（Watermark）机制
* **默认配额**：200 MB（用户可在设置中选择 100MB、200MB、500MB 或 1GB）；
* **安全水位线**：当写入新媒体导致缓存总容量超过设定阈值（如 200MB）时，不是每次删除单个文件，而是按文件的最后访问时间（`last_accessed`）升序排序，批量清理最冷的数据，直至总容量降至配额的 **80%（如 160MB）**，极大减少频繁的磁盘 I/O 抖动。

## 五、 UI 界面美学与人机工程学交互规范

### 1. “文本优先置顶 + 媒体紧凑区块化”布局
详情页摒弃传统未播放即渲染大播放器的粗暴平铺，按以下 4 层清晰排版：

```
+-------------------------------------------------------------+
|  [层级 1: 核心文本置顶]                                      |
|  • Emoji空间图腾 + 物品名称 + 规格品牌 + 数量微徽章          |
|  • 所在空间层级面包屑 (如 🧸 主卧 > 🛋️ 衣帽间 > 第2抽屉)     |
|  • 详细具体位置 + 详细备忘长文本 (舒适折行，字号 ≥14px)      |
|  • 标签流动布局 (Wrap + ShadBadge)                          |
+-------------------------------------------------------------+
|  [层级 2: 实景照片九宫格 (≤9张)]                             |
|  • 300px 极速缩略图，网格圆角 12px                          |
|  • 右上角半透明磨砂药丸 (展示尺寸与体积)                     |
|  • 点击弹出全屏沉浸画廊，支持 1.0x~4.0x 双指手势缩放         |
+-------------------------------------------------------------+
|  [层级 3: 寻路短视频区块 (≤3个)]                             |
|  • 紧凑海报卡片列表 (高度 140px，平时不实例化解码器)          |
|  • 中心带半透明播放微徽章，右下角标注 时长 | 体积            |
|  • 点击平滑展开或全屏沉浸播放，自动单播放器独占排他          |
+-------------------------------------------------------------+
|  [层级 4: 现场语音备忘区块 (≤3条)]                           |
|  • 极简圆角条状胶囊，消除沉重波形图与调试参数                |
|  • 仅展示播放微按钮、进度 mm:ss 与文件大小 (如 320 KB)       |
+-------------------------------------------------------------+
```

### 2. 多巴胺半透明磨砂药丸徽章（Frosted Glass Pill Badge）
所有多媒体组件统一挂载半透明元数据徽章：
* **背景与材质**：`Colors.black.withValues(alpha: 0.6)`，外加 `1px` 微光边框 `Colors.white.withValues(alpha: 0.2)`；
* **圆角**：`BorderRadius.circular(999)` 药丸胶囊；
* **字号与状态**：字号 `11px~12px`，明确标注格式（如 `1600x1200 | 420 KB`、`00:25 | 3.2 MB · 本地秒开` 或 `云端 1.8 MB`），给予用户明确的网络等待预期。

### 3. 单文件行数硬性红线 (<500 行) 与弹窗原则
* **严禁原生 alert/confirm**：全端统一使用 `ShadDialog`、`ShadSheet` 抽屉与 `ShadToaster` 轻量悬浮 Toast；
* **强解耦拆分**：Screen 页面仅做布局编排（控制在 200 行以内），各媒体区块独立建文件（`ItemDetailHeaderCard`、`ItemDetailImageGrid`、`ItemDetailVideoSection`、`ItemDetailAudioSection`）。

## 六、 服务端静态分发与安全防护规范

在服务端（FastAPI / Nginx 等）的分发端点中：
1. **安全沙箱防穿越校验**：所有静态路径必须在物理路径解析后校验 `target.startswith(MEDIA_DIR)`，彻底阻断越界访问攻击；
2. **HTTP 强缓存头与 ETag 协商**：
   ```http
   Cache-Control: public, max-age=31536000, immutable
   ETag: "<mtime_ns>-<size>"
   ```
   由于媒体文件采用基于年月和 UUID 的不可变命名，声明 `immutable` 允许现代浏览器、CDN 及反向代理完全跳过重复协商，实现免网络传输的缓存秒开；
3. **HTTP Range 支持**：必须支持 `206 Partial Content`，允许视频播放器拖动进度条时精准请求目标关键帧字节流。
